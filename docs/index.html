Share secrets — no server, no account

Exchange public keys with a teammate and encrypt .env.up for them — right from the editor. No cloud, no server, no signup. Just public-key cryptography.

1. Copy your public key

Right-click any .env.up → Copy My Public Key, or use the status bar menu. Your base64 key is copied to the clipboard with a fingerprint for verification. Send it to your teammate over any channel.

2. Encrypt for recipient

Right-click .env.up → Encrypt for Recipient. Paste their public key, give them a label. The file is re-encrypted for both of you — works whether locked or unlocked. Atomic write with verification ensures no data loss.

3. They decrypt with their key

Share .env.up via Git (it’s safe to commit). Your teammate runs up unlock or clicks Unlock in their editor — their private key decrypts it. No shared password, no server, no account.

CLI (terminal & CI)

For scripts, CI/CD, and AI agents. Encrypt, decrypt, and run commands with secrets — no file on disk.

npm install -g @dotenvup/cli

up init            # generate keypair
up import .env     # encrypt to .env.up
up lock            # delete plaintext
up unlock 5m       # decrypt for 5 min
up run -- npm start # no file on disk

DotEnvUp MCP — use from Cursor and AI agents

The DotEnvUp MCP server lets AI assistants (Cursor, etc.) check lock state, list key metadata, and run commands with decrypted env — without ever exposing secrets over the wire.

What is MCP?

Model Context Protocol (MCP) is a standard for connecting AI tools to external data and actions. The DotEnvUp MCP server exposes three tools: dotenvup_status (lock state, key count, drift), dotenvup_keys (key names and metadata — no values), and dotenvup_run (run a command with decrypted env; returns only exit code, not stdout/stderr, to avoid leaking secrets).

Cursor setup

Add the DotEnvUp MCP server to your Cursor MCP settings. In the extension: run DotEnvUp: Copy MCP config for Cursor from the Command Palette to copy a ready-to-paste config. Or add manually:

{
  "mcpServers": {
    "dotenvup": {
      "command": "npx",
      "args": ["-y", "@dotenvup/mcp"],
      "cwd": "${workspaceFolder}"
    }
  }
}

Requires @dotenvup/cli (same keys as the extension). Full design and tools: MCP server design (GitHub).

The .env.up Encrypted File Format

#!dotenvup v1
# Encrypted-By: @alice
# Algorithm: x25519-xchacha20-poly1305
# Encrypted-For: @alice, @bob, @ci

[keys]
DB_HOST          v3  2026-02-10T08:00:00Z  @alice    staging cluster
DB_PASSWORD      v5  2026-02-15T10:30:00Z  @alice    # rotated
API_KEY          v2  2026-02-01T00:00:00Z  @alice    test key

[encrypted]
recipient:@alice  nonce:abc123...  ephemeral:def456...  payload:SGVsbG8g...
recipient:@bob    nonce:abc123...  ephemeral:ghi789...  payload:bGQhIFRo...

Open Standard — DotEnvUp v1 Encrypted .env Specification

The .env.up format is a published open standard for encrypted environment files. Hybrid public-key encryption (X25519 + XChaCha20-Poly1305), multi-recipient support, CI/CD pipeline integration, and lossless roundtrip of comments and structure.

Read the .env.up Format Specification (v1)

Zero-Knowledge Encryption

No server, no cloud. Your private keys live only on your machine (~/.dotenvup/identity). Encrypt and decrypt locally with X25519 + XChaCha20-Poly1305.

Encrypted at Rest — Safe to Commit

Secret values, comments, and file structure are encrypted on disk. Commit .env.up to Git — it replaces both .env and .env.example.

Comments and Structure Preserved

Your # Database headers, blank lines, and commented-out secrets survive the encrypt/decrypt roundtrip with perfect fidelity.

Zero Code Changes Required

Works with existing dotenv libraries and process.env. Just up unlock to work, up lock when done. Or use up run for no-file-on-disk mode.

Visible Metadata — Half-Open Envelope

See which keys exist, who changed them, and when — without decrypting. The cleartext header replaces .env.example for onboarding.

Multi-Recipient and CI/CD Ready

Encrypt once for multiple recipients — teammates (@alice) and machines (@ci). Zero-knowledge CI/CD: up run -- npm test in your pipeline.

Edit in place — no plaintext on disk

Change secrets without ever writing a plaintext .env file. The extension opens .env.up in a virtual editor: decrypt on read, edit in memory, encrypt on save. Your disk only ever sees the encrypted file.

How it works

Right‑click .env.up in the explorer → Edit with DotEnvUp, Unlock to Disk, or Lock, or use the status bar. You get a normal-looking editor with decrypted key=value pairs. Edit, add, remove. Save (Cmd+S / Ctrl+S) — the extension re-encrypts and writes only to .env.up. No .env is created.

Why it matters

Unlock → edit .env → import → lock works, but leaves plaintext on disk while you work. Safe Edit keeps plaintext only in the editor buffer and in memory. If you walk away or the app crashes, nothing sensitive is left in a file. Same workflow as editing a normal file — just safer.

Supported use cases

All of these work with the free, open-source model — no server, no account. Full steps are in the User Guide.

  • First-time setup

    Run up init, then up import .env. If you don’t have a .env yet, create one with your keys first. Then up lock --yes to remove plaintext.

  • Daily work

    Run up unlock --duration 30m (or use the VS Code/Cursor status bar). Work with .env; it auto-locks after the duration. Or use up unlock --until-terminal-exit and lock when you exit the shell.

  • Run commands without writing .env

    Use up run -- npm start or up run -- python main.py. Decrypted env vars are injected into the process; no .env file is written. Ideal for CI/CD and AI agents.

  • Moving to another computer

    On the old machine: up key export backup.dotenvup-key. On the new machine: up key import backup.dotenvup-key, then up unlock. If you lost the key, use up recover .env.up --deep to search for key candidates.

  • Editing secrets

    Run up unlock, edit .env, then run up import .env to save into .env.up, then up lock. Or use Edit with DotEnvUp (Safe Edit) in the extension: decrypt in memory, edit, save back to .env.up without writing plaintext to disk. If both .env and .env.up exist, the extension shows “Partially protected” and can merge on unlock or in Safe Edit.

  • Sharing with one other person

    In the editor: They right-click .env.up → Copy My Public Key and send it to you. You right-click your .env.up → Encrypt for Recipient, paste their key, done. If they already publish an Ed25519 SSH key on GitHub, use Encrypt for GitHub User instead. Or CLI: they share their key via up keys --json, you run up recipients add <path-or-base64> --label alice then up import .env. Share .env.up via Git. They decrypt with up unlock — no server, no account.

  • Team recipients

    Each teammate shares their public key (right-click → Copy My Public Key, or up keys --json). Project owner adds each with Encrypt for Recipient in the editor or up recipients add ... --label name in the CLI. Teammates decrypt with up unlock. Recipients are stored in .dotenvup.recipients.json (public keys only).

  • Recover when key is missing

    If you see “encrypted with another key”, run up recover or up recover .env.up --deep to search the machine for key candidates. In VS Code/Cursor, use DotEnvUp: Recover Key Mismatch.

  • VS Code / Cursor extension

    Status bar: one-click lock/unlock; shows “Partially protected” when both .env and .env.up exist. Always visible even in empty projects (shows Init/Import). Right-click any .env.up in the explorer → Lock, Unlock to Disk, Edit with DotEnvUp (Safe Edit), Copy My Public Key, or Encrypt for Recipient. Full multi-root workspace support — all folders and subfolders are scanned. Safe Edit: open .env.up in a virtual editor, decrypt in memory, save back encrypted — no plaintext on disk. Serverless sharing: copy your public key and encrypt for a teammate directly from the context menu or status bar — no server, no account. Unlock and Safe Edit support merging when .env exists (prefer local or team). Command Palette: Unlock, Lock, Import, Show Keys, Status, Key Management, Recipients, Copy My Public Key, Encrypt for Recipient, Recover Key Mismatch. First Protect, Import All. See extension README for settings.
