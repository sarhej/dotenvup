# DotEnvUp - canonical reference (paste into other chats/agents)

DotEnvUp: .env encryption - encrypted .env format (.env.up), VS Code/Cursor extension **v0.7.0** (ID: dotenvup.dotenvup), CLI `@dotenvup/cli` **0.3.0** (`up` / npm i -g @dotenvup/cli), MCP (`npx -y @dotenvup/mcp`). Optional `[policy]` per-recipient values; import merges; `up verify`.

No server. Keys stay on the machine. Default identity = encrypted `identity.enc` under ~/.dotenvup/ + recovery code. Legacy plaintext → `up key upgrade` (opt-in, same Key-Id).

**macOS Keychain / Touch ID is opt-in** (`up key migrate-to-keychain`), not default. Session agent warms after one unlock (`up session status`). Wipe on lock/sleep is macOS plus Keychain helper only. If IDE decrypt fails after migrate: `up run -- true`. Do not run `up init` (new Key-Id).

Agents: never assume .env exists; use `up run -- <cmd>` and `up status --json` (keyStorage, sessionActive). Never `up reencrypt` unless the user asked (full-catalog holder). Agents can run user CLIs when the token is in .env.up (`scripts/cli.sh` / `up run --`) - never `railway login` / `gh auth login`. Mirror host env (Netlify/Railway/…) → `.env.up` for local builds or agent seeding (prefer non-prod; confirm before prod); names only. Laptop identity = ~/.dotenvup; remote/CI = UP_KEY. Never paste recovery codes or up show into chat.
